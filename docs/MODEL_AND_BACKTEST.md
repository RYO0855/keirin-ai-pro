# 時点管理・モデル・仮想検証

## 実装と未接続の境界

実装：条件付きロジットで選手強度を学習し、Plackett–Luceで2/3着順の同時分布を構成。校正期間で券種ごとの温度を選び、別のテスト期間で多クラスlog loss/Brier、最有力買い目のECE・的中率を計算。これは実験的な順位モデルで、走行力学・風・先行争い・体調・欠場の自動再現は未実装です。

実データで学習・校正したモデルは同梱していません。テストの人工データ・人工モデルはtests内だけで使い、APIの初期DBには入れません。

## 未来情報の排除

- イベントはSQLiteの追記専用。known_atはサーバー取込時刻。更新・削除は禁止トリガー。
- 発走前の特徴量は known_at と effective_at の両方がcutoff以前の記録だけ。成績period_endも発走より前。
- 過去データを今日取り込んでも、過去の発走前に知っていたことにはしません。そのため、取得済みデータが大量でも時点証拠不足で学習不可になることがあります。
- 訂正は新イベント。昔の分析に新しい訂正を混入させません。
- 学習/校正/テストはレースをJST日付で分け、同日のレースが跨がない60/20/20の固定分割。学習500・校正100・テスト100以上を要求。ラベルが次期間の開始前に判明していることも検査。
- データ取得前に作られた未来情報・原データ提供者による改ざんは検知できません。利用許可と出典品質は別途必要です。

## 承認と買い・ケン

モデルは自動承認しません。テストlog lossが一様分布より良く、最有力買い目の10区間ECEが0.1以下であることを最低ゲートにして、運用者が結果を確認して承認します。少数標本・分布変化・繰り返しテストによる選択バイアスには別途検討が必要で、ゲートは収益性の証明ではありません。

承認済みモデル、発走前の出走表・成績・ライン、60秒以内のオッズが揃う場合だけ、期待収益率5%以上の候補を作ります。本線2車単4点、本線3連単10点、穴目3連単8点（本線と重複せず、候補内の低確率半分）を満たさなければケン。手動の4/10/8設定は別管理で、自動上書きしません。手動設定を検証済み推奨に昇格させません。

GETの分析は記録保存ではありません。POST /v1/forecasts で再計算し、現在時刻・オッズ期限を再確認して仮想検討記録を保存します。1レース1記録。実購入なし。

## バックテスト

サーバー集計は、実際に発走前に保存した予測・その時点の承認済みモデル・オッズ証跡と、その後の確定払戻だけを使用します。的中率のほか投資・払戻・回収率・累積純損益からの最大ドローダウンを算出。結果未取得・確定払戻不足・期限外情報は除外。中止は除外します。同着・部分返還・返還額を含む精算は未対応です。

時系列ホールドアウト評価は過去の知識ログに基づく再構成です。モデルを実際にその日に運用したと主張しません。実運用の仮想検討記録集計とは分けて表示します。ブラウザ側の従来のサンプル仮想集計も残しますが、実モデル検証とは別です。

5000レースを超える学習は同期APIで実行せずoffline_job_requiredを返します。大規模バッチ/ジョブキューは未実装です。まず取得基盤と前向き記録を蓄積してください。
